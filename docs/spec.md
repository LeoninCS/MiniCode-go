# MiniCode-go 项目规格说明

> 状态：Draft  
> 范围：v0.1 项目规格

## 1. 项目概述

MiniCode-go 是一个使用 Go 从零实现的、以 CLI 为主要交互入口的轻量级 Coding Agent，可以理解为一个面向原理学习的“迷你版 Pi”。

用户通过命令行向 Agent 描述编码任务，Agent 通过大语言模型理解任务，并在用户授权的前提下使用本地工具浏览代码、修改文件、运行测试，最后返回任务执行结果。

项目希望实现的核心闭环是：

```text
理解任务
  ↓
检查代码
  ↓
制定下一步动作
  ↓
调用工具
  ↓
读取工具结果
  ↓
修改或继续分析
  ↓
运行验证
  ↓
总结结果
```

## 2. 项目定位

### 2.1 教学型项目

MiniCode-go 的主要目的不是打造一个功能最全的商业 Coding Agent，而是通过一个规模可控的项目学习以下内容：

- 模型如何调用工具；
- Agent Loop 如何工作；
- 模型、Agent 和工具之间如何分工；
- 如何让模型观察代码并采取行动；
- 如何将工具错误反馈给模型并继续恢复；
- 如何控制文件修改和命令执行权限；
- 如何验证 Agent 是否真的完成了任务。

### 2.2 简单但完整

项目会尽量减少外部框架、复杂抽象和非必要功能，但不会只实现一个“调用模型然后打印答案”的聊天程序。

首版至少应包含：

- 模型适配器；
- Agent Loop；
- 工具注册和分发；
- 文件浏览和搜索；
- 文件修改；
- 命令执行；
- 人工审批；
- 错误处理；
- 停止条件；
- 基础测试和运行日志。

### 2.3 CLI 优先

CLI 是项目首版唯一需要重点支持的交互方式。

CLI 既支持一次性任务，也支持同一会话内的多轮交互，例如：

```text
> 先分析一下这个项目的结构
> 重点看看 parser 相关代码
> 按照刚才的分析修复问题
> 运行测试验证一下
```

首版不考虑 Web UI、IDE 插件或后台常驻服务。

### 2.4 本地工作区优先

Agent 主要服务于本地代码仓库：

- 一次处理一个工作区；
- 文件操作限制在工作区范围内；
- 命令默认在工作区中执行；
- 不自动访问其他项目或远程环境。

## 3. 项目目标

### 3.1 首要目标

实现一个可以完成以下任务链的最小可用 Agent：

```text
用户提出任务
→ Agent 阅读相关代码
→ Agent 找到需要修改的位置
→ 用户批准后修改文件
→ Agent 运行测试或检查命令
→ 根据结果继续修复
→ Agent 汇报修改和验证结果
```

### 3.2 学习目标

通过项目理解：

- 对话上下文和任务状态；
- 工具定义和结构化参数；
- 模型调用与工具结果回传；
- 宿主程序对模型行为的控制；
- 代码编辑策略；
- 测试驱动的 Agent 工作流；
- 安全边界和权限审批；
- Agent 的可观测性和评测方法。

## 4. 功能范围

首版版本暂定为 `v0.1`。

### 4.1 CLI 任务入口

CLI 需要支持：

- 从命令行参数接收一次性任务；
- 从标准输入接收任务；
- 启动交互式多轮会话；
- 指定工作区路径；
- 指定模型名称和模型服务地址；
- 设置最大 Agent 轮数；
- 设置任务超时；
- 用户主动取消任务；
- 输出过程事件和最终结果。

截至 2026-10-02，交互终端已支持多行编辑、自动折行、光标移动和随光标滚动。`Shift+Enter` / `Ctrl+J` 插入换行，`Enter` 提交整段输入；上下键只在当前输入的显示行之间移动，到首末行停止，不浏览历史记录。管道输入保持逐行提交。

Ctrl+C 在输入阶段退出且不提交草稿，在运行阶段取消底层操作并退出整个会话。用户取消与任务失败的提示文案区分仍待实现。实现及验证记录见 [CLI 实现总结](cli.md)；上述状态不代表本节其他规划项均已完成。

### 4.2 会话和上下文

首版需要在单次进程运行期间保留当前会话上下文，包括：

- 用户消息；
- Agent 的阶段性回答；
- 模型工具调用；
- 工具执行结果；
- 工具错误；
- 当前工作区信息。

首版不要求实现跨进程的会话恢复和长期记忆。

### 4.3 上下文压缩

上下文压缩属于 Coding Agent 的基础能力之一，但首版只实现轻量级方案，不引入向量数据库或复杂记忆系统。

上下文压缩的目标是：在多轮读取文件、执行测试和修改代码之后，避免历史消息和工具输出无限增长，同时保留继续完成任务所需的信息。

首版压缩策略：

1. 始终保留系统规则和当前用户任务；
2. 保留最近若干轮原始对话和工具结果；
3. 将较早历史整理为滚动摘要；
4. 将过长的工具输出截断或摘要化；
5. 结构化保存任务目标、用户约束、已修改文件、测试状态、已知错误和待处理事项；
6. 需要精确信息时，重新通过文件工具读取，而不是完全依赖摘要。

压缩不得丢失以下信息：

- 用户的明确约束；
- 当前任务目标；
- 已经执行过的关键操作；
- 当前工作区和修改文件；
- 测试失败原因；
- 尚未完成的工作。

压缩触发条件可以包括：

- 估算上下文超过配置上限；
- 单次工具输出超过限制；
- 连续执行若干轮工具调用后；
- 用户主动请求压缩或总结。

首版不实现跨会话长期记忆、向量检索、全仓库 Embedding 和复杂记忆召回。

### 4.4 模型适配

模型适配层需要负责：

- 发送用户任务和系统规则；
- 注册工具名称、描述和参数结构；
- 接收普通文本回答；
- 接收结构化工具调用；
- 回传工具执行结果；
- 维护多轮上下文；
- 处理鉴权、网络、超时和响应解析错误。

Agent 核心不应直接依赖某一家模型 API，后续应能够替换模型提供方。

### 4.5 Agent Loop

Agent Loop 是项目的核心功能，负责以下流程：

1. 接收用户任务；
2. 调用模型；
3. 判断模型是直接回答还是请求工具；
4. 校验工具名称和参数；
5. 判断工具权限；
6. 必要时请求用户批准；
7. 执行工具；
8. 将工具结果或错误返回模型；
9. 重复执行，直到任务完成或停止。

必须支持以下停止条件：

- 模型返回最终回答；
- 用户主动取消；
- 达到最大模型轮数；
- 达到任务超时；
- 模型 API 发生不可恢复错误；
- Agent 内部发生不可恢复错误。

### 4.6 文件浏览工具

首版计划提供以下只读工具：

| 工具 | 功能 |
|---|---|
| `list_files` | 列出工作区中的文件和目录 |
| `read_file` | 按文件和行范围读取文本 |
| `search_text` | 在文件或目录中搜索文本或正则表达式 |
| `git_status` | 查看当前 Git 工作区状态 |
| `git_diff` | 查看当前未提交修改 |

文件浏览工具需要支持：

- 工作区相对路径；
- 文件大小限制；
- 单次输出大小限制；
- 大文件分段读取；
- 明显二进制文件过滤；
- 路径穿越检查；
- 符号链接边界检查。

### 4.7 文件修改工具

首版计划提供：

| 工具 | 功能 | 权限 |
|---|---|---|
| `edit_file` | 精确替换已有文件中的唯一文本块 | 需要审批 |
| `write_file` | 创建新文件或完整写入文件 | 需要审批 |

首版的 `edit_file` 应要求旧文本满足以下条件：

- 旧文本不能为空；
- 旧文本必须存在；
- 旧文本只能出现一次；
- 修改前文件内容必须与读取结果匹配；
- 写入过程尽量采用原子替换。

后续可以增加更强的 `apply_patch` 工具，但不作为 v0.1 的必要条件。

### 4.8 命令执行工具

当前提供 `bash{command}`，通过 `bash -c` 执行；后续可增加接收 argv 的 `run_command`。命令工具用于运行：

- 单元测试；
- 集成测试；
- 构建命令；
- 格式化命令；
- 静态检查命令。

命令工具需要支持：

- argv 参数数组；
- 指定工作目录；
- 超时控制；
- 退出码获取；
- 标准输出和错误输出捕获；
- 输出大小限制；
- 用户审批；
- 命令失败结果回传模型。

当前接入 shell 字符串并通过 `bash -c` 执行，继承启动 CLI 时的工作目录。`bash`、`write`、`edit` 默认在执行前逐次请求用户确认，拒绝后不执行并将结果回传模型；`--yes` 可自动批准。项目不提供 shell 命令内容黑名单、危险命令硬拦截、细粒度命令权限或 argv 模式，当前工作目录也不是文件系统沙箱。

### 4.9 人工审批

工具分为只读工具和副作用工具。

#### 只读工具

默认可以自动执行：

- 列目录；
- 读取文件；
- 搜索代码；
- 查看 Git 状态；
- 查看 Git diff。

#### 副作用工具

默认需要用户确认：

- 修改文件；
- 创建文件；
- 删除文件；
- 运行命令；
- 其他可能改变工作区或系统状态的操作。

审批提示应至少展示：

- 工具名称；
- 目标文件或工作目录；
- 命令或参数摘要；
- 允许和拒绝选项。

### 4.10 运行状态和日志

CLI 需要让用户能够观察 Agent 当前行为，包括：

- 当前任务；
- 当前模型轮次；
- 当前工具调用；
- 工具参数摘要；
- 审批结果；
- 工具执行成功或失败；
- 最终修改和测试结果。

后续可以增加 JSONL 事件日志，用于调试、恢复和评测，但不作为首版阻塞项。

当前交互终端使用备用屏幕展示运行过程，在最终回答、错误或取消时恢复主屏幕；最终回答留在主屏幕，中间工具输出不进入主屏幕的滚动历史。非交互模式保留完整过程输出。该展示方式不改变 Session 消息历史，token 汇总和结构化过程统计仍待实现。

## 5. 设计边界

### 5.1 首版包含

- 单 Agent；
- 单任务；
- 单工作区；
- CLI 交互；
- 多轮上下文；
- 轻量级上下文压缩；
- 基础文件工具；
- 命令执行；
- 人工审批；
- 基础安全和资源限制；
- 测试与结果总结。

### 5.2 首版不包含

- Web UI；
- IDE 插件；
- 多 Agent 和子 Agent；
- 长期记忆；
- 向量数据库和全仓库索引；
- 自动 Git commit、push 和 Pull Request；
- 自动部署；
- 复杂任务编排；
- 多工作区并行操作；
- 操作系统级沙箱；
- 后台常驻服务。

## 6. 基础安全要求

首版不是生产级安全沙箱，但必须具备基础防护：

- 文件操作限制在工作区内；
- 拒绝绝对路径和路径穿越；
- 检查符号链接是否指向工作区外；
- 限制文件、请求和工具输出大小；
- 限制模型最大调用轮数；
- 限制命令执行时间；
- 副作用工具默认需要审批；
- 不将未经用户批准的模型命令交给 shell 执行；
- 不在日志中输出 API Key；
- 明确提示：批准执行的命令和构建脚本仍可能执行任意代码，项目不提供危险命令硬拦截。

## 7. v0.1 验收标准

v0.1 至少应完成以下任务：

1. 解释一个陌生仓库的目录结构和启动流程；
2. 找到指定代码并完成一个小型修改；
3. 运行测试并根据失败信息继续修复；
4. 在工具参数错误时能够重新观察和调整；
5. 用户拒绝写入或命令执行后，操作确实不会发生；
6. 最终准确说明修改内容和真实验证结果；
7. 长任务上下文接近限制时能够进行轻量级压缩；
8. 超过最大轮数或任务超时后能够安全停止。
