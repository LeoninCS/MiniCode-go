## Day 2：工具 Schema 定义 + 工具调用响应解析 ✅

### 目标

让模型知道有哪些工具，并能够解析模型返回的工具调用。

### 内容

- ✅ 定义工具 schema；
- ✅ 定义工具名称、描述和参数；
- ✅ 解析工具调用名称；
- ✅ 解析工具调用参数；
- ✅ 校验参数 JSON；
- ✅ 区分普通文本响应和工具调用响应；
- ✅ 定义工具执行结果回传结构。

### 产出

模型可以返回类似以下信息：

```text
tool: bash
arguments: {"command":"go test ./..."}
```

程序可以稳定解析并准备执行。

已完成：

- ✅ 请求通过 `tools` 携带函数名称、描述和 JSON Schema；
- ✅ 响应支持一个或多个 `tool_calls`，并保留调用 ID、名称和原始参数；
- ✅ 参数须为顶层 JSON 对象，空值、畸形 JSON、数组、`null` 和标量会被拒绝；
- ✅ `content: null` 可无损解析和回传，工具结果使用 `role: tool` + `tool_call_id`；
- ✅ CLI 能区分文本和工具调用，展示全部合法调用但不执行；
- ✅ black-box 测试覆盖协议线格式、参数校验、多调用、结果消息和 CLI smoke。

## Day 3：Agent Loop ✅

### 目标

打通迷你版 Coding Agent 的核心循环。

### 内容

- ✅ 调用模型；
- ✅ 判断是否存在工具调用；
- ✅ 执行工具；
- ✅ 将工具结果回传模型；
- ✅ 支持多轮工具调用；
- ✅ 处理工具错误；
- ✅ 支持最终文本回答；
- ✅ 设置基础最大轮数。
- ✅ 达到轮数上限后停止工具执行，额外请求一次最终总结；总结失败时输出停止说明。
- ✅ 将循环抽到 `internal/agent`，管理模型调用、消息历史与工具分发；CLI 通过 `Output` 接口负责展示，并处理任务上下文和退出码。

### 产出

完成以下闭环：

```text
用户输入
→ 模型请求工具
→ 工具执行
→ 结果回传模型
→ 模型继续判断
→ 最终回答
```

## Day 5：系统 Prompt + CLI 输入循环 ✅

### 目标

让 Agent 从一次性调用变成可交互的 CLI 程序。

### 已完成

- ✅ 编写系统 Prompt，声明 MiniCode 身份、工作区和工具规则；
- ✅ 说明先读后改、修改后验证、限定任务范围和失败后调整策略；
- ✅ 默认进入 CLI 输入循环，位置参数作为第一轮任务；
- ✅ 同一 Session 支持连续多轮输入并保留完整消息历史；
- ✅ 系统 Prompt 始终位于消息历史首位；
- ✅ 支持 `/exit`、`/quit` 和 EOF 退出，空行直接跳过；
- ✅ 单轮失败后会话仍可继续，同时最终退出码保留失败状态；
- ✅ 文件工具工作区句柄在 Session 内复用，使“先读后改”校验可以跨轮生效；
- ✅ CLI 实现集中到 `internal/cli`，通过 `Input` / `Output` 接口与 Agent 会话解耦；
- ✅ 终端支持多行编辑、自动折行、上下光标移动和滚动显示，上下键不浏览历史；
- ✅ `Shift+Enter` / `Ctrl+J` 插入换行，`Enter` 提交整段输入；管道输入仍逐行提交；
- ✅ 运行过程使用备用屏幕，最终回答、错误和取消时恢复主屏幕。

### 产出

终端中可以连续使用，后续任务能够引用本次进程中前几轮的对话和工具结果：

```text
> 分析一下这个项目
> 重点看看 main.go
> 根据刚才的分析修改它
> 运行测试
> /exit
```

当前记忆仅存在于进程内，退出后恢复属于 Day 9。

## Day 8：Ctrl+C 中断与 context 取消 🔄

### 目标

支持用户随时停止当前任务，并正确取消底层操作。

### 已完成

- ✅ 捕获运行期间的 Ctrl+C 与 SIGTERM（`signal.NotifyContext` 位于 `internal/cli/run.go`）；
- ✅ 创建可取消的根 context，每轮任务在其之上派生带超时的子 context；
- ✅ 取消模型 HTTP 请求（`provider.Client.Chat` 用 `http.NewRequestWithContext` 构造请求）；
- ✅ 取消正在执行的 bash（命令放入独立进程组，取消时 SIGKILL 整个进程组）；
- ✅ 任务取消时回滚未配对的半轮消息，保证下一次请求合法；
- ✅ 确保资源释放（延迟关闭 Session 工作区句柄、清理残留后台命令、设置 `cmd.WaitDelay`）；
- ✅ 识别终端输入阶段传统、Kitty / CSI-u 和 xterm 编码的 Ctrl+C，退出且不提交草稿；
- ✅ 扩展键盘协议仅随输入 raw 模式启用，提交或退出后恢复，运行中 Ctrl+C 继续触发 SIGINT；
- ✅ 根 context 取消后不再启动下一轮输入，避免退出时重新进入编辑模式；
- ✅ PTY 子进程回归覆盖输入、等待模型、位置参数任务及终端状态恢复。

### 待补

- ⬜ 区分用户取消和任务失败：当前两者都经 `ToolError` 打印为 `context canceled` 一类的原始错误，提示文案没有区分；
- ⬜ 输出明确的任务中断状态：CLI 没有「任务已中断」这类结论性提示，只打印错误并返回退出码。

### 产出

用户按下 Ctrl+C 后退出整个会话，Agent 不会继续执行后续工具；输入模式、扩展键盘协议和备用屏幕得到恢复。当前中断退出码为 `1`，提示文案区分仍待补充。

## Day 14：压缩切分点合法性处理 ⬜

### 目标

保证上下文压缩不会破坏会话结构。

### 内容

- 压缩失败时保留原始上下文并安全退出或重试。

### 产出

## v0.1 完成标准

当以下流程可以稳定运行时，认为 v0.1 基本完成：

```text
CLI 输入任务
→ 模型分析
→ 调用 bash 查看或验证项目
→ 用户确认后写入文件
→ 继续调用模型
→ 运行测试
→ 测试失败后继续修复
→ 输出最终总结
```

同时满足：

- 有最大轮数；
- 有超时和取消；
- 有工具输出限制；
- 有执行前确认；
- 有 Session 保存和恢复；
- 有 SSE 流式输出；
- 有上下文压缩；
- 有基本测试和过程可视化。
