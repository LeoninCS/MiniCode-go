# MiniCode-go 开发计划

> 目标：用 Go 实现一个面向学习的迷你版 Pi。  
> 交互方式：CLI 优先。  
> 当前状态：Day 0 已完成，Day 1～Day 14 待开始。

## 状态标记

- ✅ 已完成
- ⬜ 未开始
- 🔄 进行中
- ⏸️ 暂缓或延期

## 总体阶段

```text
Day 0          项目规划
Day 1～Day 8   基础可用版：非流式 Agent + 工具 + CLI + 安全控制
Day 9～Day 10  可持续运行版：Session + Provider 抽象
Day 11～Day 12 交互增强版：SSE 流式输出 + 工具参数分片
Day 13～Day 14 长任务版：上下文压缩与合法切分
```

## Day 1：协议结构体 + 单次非流式模型调用 ⬜

### 目标

完成模型 API 的最小非流式调用链路。

### 内容

- 定义请求结构体；
- 定义响应结构体；
- 定义消息、错误和响应内容结构；
- 实现 HTTP 请求；
- 处理鉴权和基础错误；
- 完成一次用户输入到模型文本输出的调用。

### 产出

- 可以发送一条文本请求；
- 可以解析模型返回的文本；
- API 错误能够被明确报告。

---

## Day 2：工具 Schema 定义 + 工具调用响应解析 ⬜

### 目标

让模型知道有哪些工具，并能够解析模型返回的工具调用。

### 内容

- 定义工具 schema；
- 定义工具名称、描述和参数；
- 解析工具调用名称；
- 解析工具调用参数；
- 校验参数 JSON；
- 区分普通文本响应和工具调用响应；
- 定义工具执行结果回传结构。

### 产出

模型可以返回类似以下信息：

```text
tool: bash
arguments: {"command":"go test ./..."}
```

程序可以稳定解析并准备执行。

---

## Day 3：Agent Loop ⬜

### 目标

打通迷你版 Coding Agent 的核心循环。

### 内容

- 调用模型；
- 判断是否存在工具调用；
- 执行工具；
- 将工具结果回传模型；
- 支持多轮工具调用；
- 处理工具错误；
- 支持最终文本回答；
- 设置基础最大轮数。

### 产出

完成以下闭环：

```text
用户输入
→ 模型请求工具
→ 工具执行
→ 结果回传模型
→ 模型继续判断
→ 最终回答
```

---

## Day 4：bash、write_file 工具 + 工具注册表 ⬜

### 目标

让 Agent 能够真正操作本地工作区。

### 内容

- 实现 `bash` 工具；
- 实现 `write_file` 工具；
- 定义统一工具接口；
- 实现工具注册表；
- 根据工具名称分发调用；
- 为工具生成 schema；
- 统一处理工具成功和失败结果。

### 注意

`bash` 是能力较强的通用工具，首版必须配合：

- 工作目录限制；
- 超时；
- 输出截断；
- 执行前确认；
- 基础危险命令限制。

后续可增加更细粒度的 `read_file`、`edit_file`、`list_files` 和 `git_diff` 工具，减少对 `bash` 的依赖。

## Day 7：Token 统计 + 过程可视化 ⬜

### 目标

让用户能够看到 Agent 的运行过程和资源消耗。

### 内容

- 统计输入 token；
- 统计输出 token；
- 统计总 token；
- 统计模型调用次数；
- 统计工具调用次数；
- 展示当前轮数；
- 展示当前工具；
- 展示工具执行成功或失败；
- 展示累计耗时。

### 产出

CLI 能够展示类似：

```text
[turn 3] calling bash
[tool] completed in 1.2s
[tokens] input: 3200, output: 540, total: 3740
```

## Day 8：Ctrl+C 中断与 context 取消 ⬜

### 目标

支持用户随时停止当前任务，并正确取消底层操作。

### 内容

- 捕获 Ctrl+C；
- 创建可取消的根 context；
- 取消模型 HTTP 请求；
- 取消正在执行的 bash；
- 区分用户取消和任务失败；
- 确保资源能够释放；
- 输出任务中断状态。

### 产出

用户按下 Ctrl+C 后，Agent 不会继续执行后续工具，也不会留下无法回收的任务。

---

### 目标

让 CLI 会话可以保存，并在下次启动时恢复。

### 内容

- 定义 Session 数据结构；
- 保存用户消息；
- 保存模型响应；
- 保存工具调用和工具结果；
- 保存当前工作区信息；
- 保存任务状态；


### 内容

### 目标

### 内容

- 建立 SSE HTTP 请求；
- 解析 event 和 data；
- 处理增量文本；
- 处理结束事件；
- 处理流式错误；

## Day 12：tool_calls 参数分片累积 + 打字机输出 ⬜

### 目标

完善流式文本和流式工具调用体验。

### 内容

- 累积分片的工具名称；
- 累积分片的工具参数；
- 处理参数 JSON 尚未完整的中间状态；
- 在工具参数完整后再执行工具；
- 实现文本打字机输出；
- 区分文本增量和工具调用增量；
- 处理流式响应结束前的异常。

### 产出

CLI 可以像终端 Agent 一样边生成边显示，并在参数接收完整后执行工具。

---

## Day 13：上下文压缩触发与摘要 ⬜

### 目标

避免长任务导致上下文无限增长。

### 内容

- 估算当前上下文大小；
- 设置上下文预算；
- 判断是否触发压缩；
- 保留系统规则和当前任务；
- 保留最近若干轮消息；
- 生成旧消息摘要；
- 摘要工具调用和工具结果；
- 保存已修改文件和测试状态；
- 支持用户主动执行 `/compact`。

### 产出

上下文接近限制时，Agent 可以继续任务，而不是因为历史过长而失败。

---

## Day 14：压缩切分点合法性处理 ⬜

### 目标

保证上下文压缩不会破坏会话结构。

### 内容

- 不在单条消息中间切分；
- 不拆分工具调用和工具结果；
- 不丢失未完成的工具调用；
- 不丢失用户约束；
- 不丢失任务目标；
- 不丢失当前工作区状态；
- 不在 JSON 参数未闭合时切分；
- 压缩后校验消息序列合法性；
- 压缩失败时保留原始上下文并安全退出或重试。

### 产出

压缩后的上下文仍然可以被模型正确理解，并继续执行工具调用。

## v0.1 完成标准

当以下流程可以稳定运行时，认为 v0.1 基本完成：

```text
CLI 输入任务
→ 模型分析
→ 调用 bash 查看或验证项目
→ 用户确认后写入文件
→ 继续调用模型
→ 运行测试
→ 测试失败后继续修复
→ 输出最终总结
```

同时满足：

- 有最大轮数；
- 有超时和取消；
- 有工具输出限制；
- 有执行前确认；
- 有 Session 保存和恢复；
- 有 SSE 流式输出；
- 有上下文压缩；
- 有基本测试和过程可视化。
